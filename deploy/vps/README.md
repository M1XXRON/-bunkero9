# Переезд сайта на VPS (Timeweb)

Цель: `https://bunker9.lol` работает независимо от ноутбука. Схема:

```
интернет -> Caddy (TLS Let's Encrypt) -> node server.js на 127.0.0.1:3100
```

Туннель Cloudflare на ноутбуке остаётся как резерв: если VPS упадёт, DNS
переключается обратно на туннель за минуту.

---

## 1. Что создать в Timeweb

**Облачные серверы → Создать сервер:**

| Параметр | Значение |
|---|---|
| Локация | Россия (Москва / СПб) — ближе к игрокам |
| ОС | **Ubuntu 24.04** |
| Конфигурация | минимальная: 1 vCPU, **1 ГБ RAM**, 10–15 ГБ SSD |
| IPv4 | включить (обязательно) |
| SSH-ключ | добавить публичный ключ с ноутбука (см. ниже) |
| Резервные копии | по желанию, для игры не нужны |

1 ГБ RAM хватит с большим запасом: процесс держит комнаты в памяти,
нагрузка — один socket.io на 15 человек.

**Публичный ключ** (вставлять целиком одной строкой):

```bash
cat ~/.ssh/id_ed25519.pub
```

Если при создании ключ добавить нельзя — создай сервер с паролем от root,
зайди по паролю один раз и выполни:

```bash
mkdir -p ~/.ssh && echo 'СЮДА_СВОЙ_ПУБЛИЧНЫЙ_КЛЮЧ' >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
```

## 2. DNS в Cloudflare

Сейчас `bunker9.lol` и `www` — CNAME на туннель. Перед первым деплоем
замени их на A-записи сервера:

| Type | Name | Content | Proxy |
|---|---|---|---|
| A | `bunker9.lol` | IP сервера | **DNS only (серое облако)** |
| A | `www` | IP сервера | **DNS only (серое облако)** |

Удалить оба CNAME на `*.cfargotunnel.com`.

Важно: **серое облако**, а не оранжевое. Caddy должен сам получить сертификат
Let's Encrypt; при оранжевом облаке TLS терминирует Cloudflare и нужен
отдельный origin-сертификат — это следующий шаг, а не первый.
Оранжевое облако можно включить потом, когда сайт уже работает: тогда SSL-режим
в Cloudflare ставится `Full (strict)`.

## 3. Деплой

```bash
cd ~/Desktop/bunker
VPS_HOST=203.0.113.10 ./deploy/vps/deploy.sh
```

Что произойдёт:

1. проверит SSH;
2. скопирует проект в `/opt/bunker9/app` (без `node_modules`, тестов и скриншотов);
3. поставит на сервере Node 22, Caddy, `ufw`, создаст пользователя `bunker`
   и systemd-юнит `bunker9`;
4. выполнит `npm ci --omit=dev`;
5. перезапустит сервис и прогонит `deploy/smoke.sh`.

Повторные выкладки — та же команда: код обновится, зависимости встанут, сервис
перезапустится. Первый запуск займёт 2–3 минуты, следующие — секунд двадцать.

## 4. Проверка

```bash
./deploy/smoke.sh                                   # снаружи, по домену
ssh root@IP 'systemctl status bunker9 --no-pager'    # сервис
ssh root@IP 'journalctl -u bunker9 -n 30 --no-pager' # логи приложения
ssh root@IP 'journalctl -u caddy -n 20 --no-pager'   # логи Caddy и выдача TLS
```

`smoke.sh` проверяет: 200 на главной, свой `<title>`, свой `/health`, QR, 301 на www.
Именно он ловит случай «по домену отдаётся чужое приложение».

## 5. Если что-то пошло не так

**Сертификат не выдаётся.** Caddy пишет в `journalctl -u caddy`. 99% случаев —
A-запись ещё старая (DNS не успел, TTL 300 с) или включено оранжевое облако.
Проверить: `dig +short A bunker9.lol @1.1.1.1` должен вернуть IP сервера.

**Сайт отдаёт 502.** Node не поднялся: `systemctl status bunker9`, затем
`journalctl -u bunker9 -n 50`. Частая причина — не встали зависимости
(`npm ci`), тогда повторить деплой.

**Надо срочно вернуть сайт на ноутбук.** В Cloudflare вернуть CNAME на туннель
(`bunker9.lol` → `16e8a7bf-b407-4229-a1b3-d01d0b4a226d.cfargotunnel.com`,
оранжевое облако), на ноутбуке:

```bash
launchctl kickstart -k gui/$UID/lol.bunker9.web
launchctl kickstart -k gui/$UID/lol.bunker9.tunnel
./deploy/smoke.sh
```

На ноутбуке всё остаётся установленным и рабочим — туннель никуда не удаляем.
