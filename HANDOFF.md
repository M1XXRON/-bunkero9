# HANDOFF — БУНКЕР·9 (веб-версия)

Обновлено: 14 ноября 2026, утро.

## TL;DR

**Прод: https://bunker9.lol** — Bun-бинарник на VPS, HTML по SSE через Datastar.

```
интернет → Cloudflare → Caddy (TLS) → bunker9.service :3100 → SQLite
```

- Код: `~/Desktop/bunker` (git, `main`, 49 коммитов, сторонних зависимостей нет).
- Рантайм: Bun 1.4.4, `~/.bun/bin/bun`. В неинтерактивном шелле `bun` не в
  `PATH` — либо `export PATH="$HOME/.bun/bin:$PATH"`, либо полный путь.
- Движок: `src/engine.js` (CommonJS), без ролей и «мафии»: выживание до
  спасения, минимум смены, карты с эффектами.
- Состояние: SQLite `bun:sqlite` — `rooms`, `sessions`, `games`.
- Тесты: `bun run verify` (гейт), браузерные — отдельно.

**Native-версия заморожена.** Каталог `~/Desktop/bunker-odin` (Odin + raylib)
остаётся на диске как архив, но в работе не участвует: файлы, процессы и
документацию там не трогаем. Всё развитие — в `~/Desktop/bunker`.

## Архитектура

```
server.ts
  Bun.serve: GET /            лендинг или приложение
             GET /stream      SSE-поток, патчи HTML по id
             POST /act/:cmd   действия (create/join/start/reveal/vote/chat/…)
             GET /health      комнаты, сессии, база
             GET /api/games   последние 10 партий
src/engine.js   правила и состояние комнат (единственный источник правды)
src/render.ts   состояние → HTML (topbar, board, tabs, feed)
src/store.ts    bun:sqlite; rooms/sessions/games, отложенная запись 200 мс
src/ai.ts       OpenAI-совместимый клиент, 6 генераторов, режим mock
src/content.js  карты, эффекты, события, сценарии, концовки, аватарки
public/         style.css, sound.js (WebAudio), vendor/datastar-1.0.5.js
```

Один SSE-поток на игрока; действий — обычные POST, ответ 204/303. Сервер сам
считает, какие карты и каналы чата видны каждому (`serializeFor`), скрытые
значения в чужие снимки не попадают.

## Инварианты и грабли (не сломать)

1. **Сценарий без таймера.** `startGame` открывает `intro` с
   `phaseEndsAt=null`; день начинается по `markReady` (все прочитали, боты
   отмечаются автоматически) или по хосту через `skip`. После рестарта
   `resumeRoom` не вооружает таймер для intro. Кнопки — `.intro-ready` и
   `.intro-start`, счётчик — `snap.ready`.
2. **Таймер фазы ставит сервер.** `endsAt`/`left` приходят в сигналах Datastar.
   `data-signals__ifmissing` не перезаписывает существующий сигнал, а топбар
   морфится каждый патч — с `ifmissing` таймер навсегда застревал на 0.
3. **`/stream` = игрок онлайн.** После рестарта `resumeRoom` помечает всех
   `connected:false`, а `broadcast` таким ничего не шлёт. Поэтому поток
   выставляет `connected:true` и рассылает снимок; иначе вкладки замирают.
4. **SSE keepalive.** Cloudflare рвёт простойный ответ ~100 с; комментарий раз
   в 15 с и `retry:'always'` на клиенте держат поток живым.
5. **`BUNKER_TEST=1` — только для ботов.** HTTP-проверкам нужны настоящие
   таймеры, иначе фазы уезжают вперёд. `verify` поднимает два сервера.
6. **Припасы выдаются при вскрытии карты**, не на старте. Экономика зависит от
   того, что игроки реально показали.
7. **Спасение — после последнего кризиса и только с запасами.** `finishDay`
   вызывается из `resolveCrisis` после голосования: `день >= rescueDay` даёт
   победу только при `food > 0 && energy > 0`, иначе «БУНКЕР МОЛЧИТ» с
   объяснением в ленте. Медикаменты — буфер кризиса, не действие. Старые
   комнаты из базы со state=night доводятся `resolveLegacyNight`.
   Стартовые запасы — `R·N + 6` еды и `энергия/день · R + 4`; старый запас
   «на день меньше» больше не доживает до спасения.
8. **Комнаты и сессии в SQLite.** `resumeRoom` восстанавливает таймер и
   `timeoutFn` по текущей фазе; `socketId` не сериализуется.
9. **Брошенные комнаты убираются** по живости SSE + `BUNKER_IDLE_MIN` (30 мин);
   в лобби отключившийся удаляется через 120 с.
10. **Рендер экранирует пользовательский текст** (`esc`), имена и чат чистятся
    от управляющих символов и `<>`.
11. **Мобильный режим — отдельный слой.** Вся мобильная раскладка живёт в
    `@media (max-width: 780px)` в конце `public/style.css`; десктопные правила
    не трогаются. Вкладки «Стол/Чат» — состояние `html[data-mtab]`, потому что
    `#board` перерисовывается каждым патчем, а оболочка нет. Сервер отдаёт на
    `#board` атрибуты `data-action` (точка на «Столе»), `data-phase` (скрыть
    событие в vote/night/reveal) и `data-my-turn` (спрятать досье в свой ход).
    Поле ввода не уезжает под клавиатуру: JS пишет `--app-h` из
    `visualViewport`. Непрочитанный чат — класс `has-unread` по приросту числа
    узлов ленты (замена ленты Datastar не считается новым сообщением).
12. **Карты: восемь характеристик и ранги.** `TRAITS` в `content.js` —
    пол/возраст, рост/вес, здоровье, профессия, хобби, багаж, крупный багаж,
    спецвозможность. Эффект ищется по полному значению, затем по первому и
    последнему сегменту до «·»: «повар · 4 разряд» = «повар»,
    «астма · тяжёлая» = «тяжёлая». Так ранги/степени не ломают экономику.
    Спецвозможности — `SPECIALS` и `useAbility` в движке: `НЗ` сразу,
    `обмен` (карта → игрок) и `разведка` (приватное сообщение `to`). Одна
    на партию, только днём; ожидание хранится в `room.ability`, сбрасывается
    после голосования (кризис), при смерти/выходе и рематче.
13. **Голосование показывает цену изгнания.** `leaveCost` в снимке считается
    через `costFor(..., revealedOnly=true)`: только раскрытые карты, поэтому
    скрытые повара/ожирения не утекают. В карточке цели — «≈ если изгнать:
    −N еды · −M энергии/день», зелёным экономия, красным рост расхода.
14. **НЗ масштабируется по составу.** `specialSupply(total)` в `content.js`:
    еда `max(6, N)`, энергия `max(4, ⌈N/3⌉)`, +1 медикамент; описание в
    досье/правилах собирается динамически.
15. **Очередь раскрытия сдвигается по дням, первый день — два круга.** За
    порядок отвечает `turnOrder(room)` (offset = день−1), а `room.turn.pass`
    держит круг. После первого круга дня 1 `advanceTurn` сбрасывает
    `revealedThisRound` и запускает второй; ключ `botPhase` в `server.ts`
    обязан включать `pass`, иначе бот не сходит во втором круге.
16. **Подсветка влияния карт и мигание ресурсов.** `traitImpact` в движке
    помечает вскрытую карту `gain`/`drain` (припасы — сразу, ранги/степени —
    суточный расход) и кладёт это в сообщение раскрытия и `traitSlots` только
    для раскрытых карт. Топбар красит ресурс в `warn` (запас на 2 дня) и
    `crit` (на день) с CSS-анимацией `res-blink`; reduced-motion её выключает.
17. **SSE сжимается на лету** (zstd, фолбэк brotli). Заголовок `Content-Encoding`
    фиксируется при открытии потока — переключать алгоритм посреди ответа нельзя;
    после каждого патча обязателен `flush()`, иначе события копятся в буфере.
    Caddy не должен сжимать ответ второй раз (у нас уже стоит `Content-Encoding`;
    в `cache-control` добавлен `no-transform`).

## ИИ

Включён на проде: **OpenCode Go**, `BUNKER_AI_URL=https://opencode.ai/inference/go/openai/v1`,
модель `glm-5.3-flash`, таймаут 25 с. Ключ — `oc_sk-…`, только в drop-in юнита.
Без ключа всё работает на фолбэках — игра не ломается, просто нет сюжета от
модели, персонажей, события, подсказок, эпитафий и разбора.

Особенности шлюза:

- обязателен заголовок `x-opencode-session` (без него 400 `MissingSessionID`);
  `ai.ts` отправляет его автоматически, id — на процесс или `BUNKER_AI_SESSION`;
- шлюз просит свой `user-agent`, а не SDK — отправляем `bunker9-game/2.0`;
- reasoning-модели тратят `max_tokens` на размышления и обрывают JSON. Рабочий
  режим для GLM — `BUNKER_AI_REASONING=low`: 0 reasoning-токенов, 1–3 с на вызов.
  `none` у GLM иногда отдаёт 400 «Endpoint is unavailable», а без параметра
  модель тратит 850–1450 reasoning-токенов и 8–12 с на вызов;
- GLM 5.3 Flash иногда «думает»: в usage прилетает 0–1400 reasoning-токенов,
  и на маленьком `max_tokens` JSON обрывается (`finish_reason=length`) или
  приходит пустым. Поэтому бюджеты подняты (персонажи 3000, разбор 2500,
  остальное 1500–2000), а `chatJson` делает один повтор с удвоенным лимитом
  (до 4000);
- 15 персонажей генерируются до ~16 с, но старт их не ждёт: не успели — карты
  из `content.js`;
- меню моделей и лимитов: `/docs/console/go`, список — `GET …/go/openai/v1/models`.

Проверка на mock (без сети): `bun tools/ai-e2e.mjs` (входит в `verify`).
Ключ меняется только в drop-in юнита + `systemctl restart bunker9`; в репозиторий
не коммитить и не печатать в логи.

Прод-конфиг (значения, не секреты):

```
BUNKER_AI=live
BUNKER_AI_URL=https://opencode.ai/inference/go/openai/v1
BUNKER_AI_MODEL=glm-5.3-flash
BUNKER_AI_TIMEOUT_MS=35000
BUNKER_AI_KEY=<ключ OpenCode Go, только в ai.conf>
```

## Деплой и откат

`deploy/vps/deploy.sh` делает по порядку: `verify` → компиляция
(`bun build --compile --bytecode --target=bun-linux-x64`) → ssh → rsync бинарника
и кода в `/opt/bunker9/app` → идемпотентный `bootstrap.sh` (юнит, Caddy, права) →
`systemctl restart bunker9` → `/health` → `smoke.sh`.

Важно:

- **Отката из коробки нет**: бинарник на сервере перезаписывается. Перед
  выкладкой стоит сохранить текущий:
  `ssh root@45.15.67.190 'cp /opt/bunker9/app/dist/bunker9 /opt/bunker9/app/dist/bunker9.prev'`
  (вернуть — скопировать обратно и `systemctl restart bunker9`).
- **Бэкап базы**: `sqlite3` на VPS нет, WAL. Безопасно так:
  `systemctl stop bunker9`, скопировать `bunker.db` + `-wal` + `-shm`, `systemctl start bunker9`.
- Секреты и `data/` на сервере не перезаписываются (rsync исключает `data`).
- `smoke.sh` проверяет, что по домену отдаётся именно бункер (заголовок, `/health`).

## Открытые вопросы и следующие шаги

1. **Перевыпустить ключ OpenCode Go.** Текущий ключ (`oc_sk_…`) попал в чат и
   во временный файл; в репозиторий не попал, но его стоит заменить и оставить
   только в `ai.conf` (600 root). После замены — `systemctl restart bunker9`.
2. Локальный `:3100` (PID менялся) может работать на старом коде — перезапустить
   `bun run server.ts`, если нужен паритет с продом.
3. Аккаунты/статистика/модерация — не начаты; сейчас всё анонимно и без бана.
4. Горизонтального масштабирования нет: один процесс, комнаты в памяти + SQLite.
5. Анимации карт/голосования и EN-локализация — из идей, не начаты.
6. Баланс: `balance-sim` полезен, но выводы по нему не фиксировались.
7. zstd до браузера доходит только напрямую; через Cloudflare — brotli
   (CF срезает `zstd` из `Accept-Encoding`). Если нужен zstd и через прод —
   вопрос к настройкам Cloudflare, не к коду.
